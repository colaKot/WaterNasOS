# 依赖升级真机回归测试计划

> 适用版本：2026-10-17 依赖升级批次（plus 系整组升 + file_picker 13 适配 + sqlite3 3.x + Flutter 3.47.7）
> 目的：验证 **file_picker 13 的 19 处业务改动** 与 plus 系原生实现替换没有破坏既有功能。
> 用法：按 P0 → P1 → P2 顺序执行；每条都标了「失败时先去查哪里」，便于直接定位代码。

## 零、开测准备

### 环境

| 项 | 要求 |
|---|---|
| 服务端 | `dist_v34`（已含依赖升级） |
| 客户端 | 今天的构建：`flutter_client/build/windows/x64/runner/Release/WaterNasClient.exe` / `build/app/outputs/flutter-apk/app-release.apk` |

| 测试数据 | 准备：小图(<1MB)、大图(>10MB)、视频(.mp4)、音频、PDF、zip、一个**中文名文件**、一个**空格+特殊字符名文件**、一个空文件(0 字节) |

### 三个必测平台

| 代号 | 平台 | 为什么必须测 |
|---|---|---|
| **A** | Android 客户端 | 主端，`path` 有值，走文件路径分支 |
| **W** | 手机浏览器（web） | **`path` 恒为 null，走 `readAsBytes` 内存分支 —— 本轮最危险的地方** |
| **D** | Windows 客户端 | 桌面端，`path` 有值，且 `lengthSync` 修复只在这里生效 |

> 手机浏览器和 Android 客户端**代码路径不同**，必须分别测，不能互相替代。

## 一、P0 必测（任何一条失败都不要发版）

### P0-1 快速上传（普通文件）· 平台 A / W / D

- **入口**：首页 → 快速上传（或任务中心 → 上传）
- **操作**：点上传 → 选 3 个文件（含一个大文件、一个中文名文件）
- **预期**：
  1. 选择器能弹出（弹不出 = `file_picker 13` 原生实现有问题）
  2. 选完出现确认框，提示「是否立即开始」
  3. 任务出现在「上传中」，**文件大小显示正确**（不是 0 B）
  4. 上传完成，服务器上文件大小与原文件一致
- **失败先查**：
  - 选择器弹不出 → `upload_center_uploading_tab.dart:_pickFiles`
  - 大小显示 0 B / 提示「空文件已跳过」→ `upload_controller.dart:280` 的 `lengthSync`（**这条修复只在 A/D 生效，W 不走这段**）
  - 上传后大小为 0 → `notes_api_service` 同类问题，查 `XFile` 构造

> ⚠️ 这是本轮**改动最密集**的一条。`upload_controller` 的 `size` 判断从 `pickedFile.size` 改成了 `lengthSync() ?? await length() ?? 0`，必须确认大小不是 0。

### P0-2 笔记插图 · 平台 A / W（重点）

- **入口**：笔记 → 打开一篇笔记 → 插入图片
- **操作**：选一张 JPG → 等上传完成 → 关闭笔记重新打开
- **预期**：图片能插入、能显示、**重启应用后仍在**
- **失败先查**：`notes_api_service.dart:332-372` 的 `uploadAsset`

> ⚠️ **这是全项目语义改动最微妙的地方**。原来靠 `file.bytes != null` 决定「走内存」还是「走文件」，现在改成按 `filePath.isNotEmpty` 判断。
> **W 端 `path` 为 null，会走 `readAsBytes()` 分支**；A/D 走 `MultipartFile.fromFile`。
> 三个平台都要过，尤其是 web。

### P0-3 web 端文件选择（无 path 分支）· 平台 W

- **入口**：任选一个用 `FilePicker` 的地方（推荐快速上传 + 壁纸设置）
- **操作**：在手机浏览器里选文件并完成一次真实上传
- **预期**：上传成功，无「上传失败」「文件为空」
- **失败先查**：所有 `_addPickedPlatformFilesToUpload` / `readAsBytes` 分支

> ⚠️ web 上 `PlatformFile.path == null`。代码里有多处 `if (path.isEmpty) continue;`，如果某个入口在 web 上被误判成"无文件"，会**静默跳过、界面无反应**（不报错）。所以判定标准是「有没有真的传上去」，不是「有没有报错」。

### P0-4 上传页能正常显示（不要灰块）· 平台 W

- **入口**：手机浏览器 → 上传页 / 快速上传页 / 下载中心「已下载」tab
- **预期**：正常显示列表或「暂无数据」，**不能是一整块灰色矩形**
- **失败先查**：`upload_center_uploading_tab.dart:606`、`download_center_downloaded_files_tab.dart:49` 的 `!kIsWeb && Platform.isIOS`

> 灰块 = release 模式的渲染错误。这两处已修（`Platform.isIOS` 在浏览器抛异常），但**必须回归确认**。
> 顺带把**所有**页面快速点一遍，看有没有别的灰块 —— `Platform.isX` 在 web 上一个都不能裸调。

### P0-5 登录 / 会话 · 全平台

- **操作**：全新登录 → 杀掉应用重启 → 确认免登录 → 手动退出 → 再登录
- **预期**：全程正常，不被踢出
- **失败先查**：服务端 `authService` / `user_token` 表

> 今天已出现过一次「token 刷新失败 → 大量模块消失」的假象，务必确认登录态稳定。

## 五、判定标准

**可以发版**：
- P0 全过
- P1 全过（或失败项已定位为本轮之前就存在的问题）
- P2 无阻断性问题

**不要发版**：
- P0 任一条失败
- 出现灰块
- web 端"选了文件但没反应"（静默跳过的典型表现）
- 上传后文件大小不对

---

## 六、出问题时的定位顺序

1. **先看是不是灰块** → `Platform.isX` 在 web 上裸调 → 搜 `lib/modules/*/views/` 里没加 `!kIsWeb` 的
2. **选了文件没反应** → `if (path.isEmpty) continue;` 把 web 的文件滤掉了
3. **文件大小 0 / 提示空文件** → `lengthSync()` 返回 null 但没走 `await length()` 兜底
4. **上传成功但内容为空** → `notes_api_service` 那类 bytes/files 分支选错了
5. **选择器根本不弹** → `file_picker 13` 原生插件问题，回退 `pubspec.yaml` 里的 `file_picker` 到 `^10.3.7`（同时 `share_plus` 要退回 `^10.1.4`，二者被 `win32` 版本绑定）
