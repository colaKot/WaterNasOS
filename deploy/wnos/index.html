Windows NAS · 服务端

一台 Windows 电脑，就是你的 NAS

不用刷机、不用买专用设备、不用折腾群晖。服务端常驻在普通 Windows 机器上，一个进程同时提供 API、索引、转码、识别与同步通道。

它是什么

服务端（electron_server）是整套系统的心脏，基于 Electron + Express 实现，常驻 Windows x64 运行， 负责照片与影视索引、ffmpeg 转码、AI 识别、同步通道和全部 553 个 API 路径。桌面端、安卓三端、TV 与网页端，连的都是同一个它。

数据只在你自己家

所有数据落在本地磁盘与 SQLite，不经过任何公有云；多用户账号、相册按用户隔离、AES 加密空间全部在本地完成。 拔掉外网，内网照用不误；缩略图与索引缓存目录还能整体搬到别的盘。

能跑在什么机器上

Windows 10 / 11 x64 即可，普通家用机、旧笔记本、迷你主机都行。有 NVIDIA 显卡时自动用 DirectML 加速推理，没有就用 CPU， 模型与第三方运行时随安装包一起给，解压即用。

本地 AI 识别

所有推理都在你自己的机器上跑

没有云端调用、没有上传队列、没有按次计费。模型随安装包给到本地，ONNX Runtime 直接在本机推理， 断网也能持续识别；NVIDIA 显卡走 DirectML，没有显卡就用 CPU 慢慢跑。

  • 人脸：EdgeFace 检测 → 512 维特征 → 聚类成「人物」，可合并、拆分、命名、管理样本。
  • 场景：SigLIP2 base-224 + DETR-R50 多标签，带「可判性」闸门——人像与静物不会乱贴风景标签。
  • 活动：独立维度（游泳 / 跑步 / 大笑 / 合影 / 婚礼 / 聚会…），与场景分开存储、可单独重置。
  • 语义：CLIP 双塔 + 512 条中文短语最大匹配 → 有序绑定，中文描述不用先翻英文。

能力实现与取舍
人脸EdgeFace：检测 → 512 维特征 → 聚类成「人物」，支持合并 / 拆分 / 命名 / 样本管理；展示层有最小出现次数闸门，具名人物不受限。

OCRPP-OCRv6 small，缺 v6 时自动回退 v5，阈值按版本走；票面、截图、路牌、文档都能读。
语义搜索CLIP 双塔 + 本地词表最大匹配 + 有序绑定 + 迟到融合；另有多语言第二路召回兜底，不用绝对阈值硬判。
向量检索向量下沉 SQLite（sqlite-vec），数万张照片的近邻检索从 509ms 降到 106ms。
回忆与叙事

机器提议，人来确认

「同一天 + 同一片地方 + 一堆照片」会先算成候选记忆，只有你点了确认才算数。卡片上写清楚「地点 · 干了什么 · 张数」， 不编故事、不硬凑；不想看的可以忽略，也能把某张照片移出这段记忆（原图不动）。

  • 人生章节：按年成书，一页 = 一天；左页大图 + 本日精选，右页影像日记 + 地点 + 标签，键盘与鼠标都能翻。
  • 一日一帧：每天挑一张代表作，配当日标签与地点。
  • 票夹：识别火车票 / 机票 / 电影票，按行程归组，出差与旅行自动整理成册。
  • 年度记录与时光对照：按年统计张数、覆盖地点、活跃人物、常用场景；同一地点可跨年份对照。

足迹地图

角标写多少张，点开就是多少张

同一位置的照片会互相压盖，几乎每个相册都有这个毛病。WaterNasOS 用世界像素距离聚成簇， 落点取簇内最密那张的真实坐标——聚合后在数学上不可能互相压盖；平移不重算，只在缩放或数据变化时重算。

  • 点开范围 = 格集合：某簇覆盖的 geohash 格用 WHERE IN 一次取回，角标数字与列表张数严格相等。
  • 地名取真实最近：按经纬度实际距离取最近地名（30km 闸门），只显示一种语言，有中文就不拼英文。
  • 精度按需解析：按格子数上限解析式选择精度，不会为了全量加载把内存撑爆。
  • 可切换地图源：默认内置瓦片，也能换成自己的底图。

票票夹与行程

OCR 读出火车票、机票、电影票的关键字段，按时间与行程归组；出差回来不用再翻相册找那张报销凭证。

清重复与相似清理

重复按内容 MD5 分组、相似按特征聚类；清理先预演再执行，撤销能回到清理前。只在恰好留一张时合并收藏、相册、场景、活动、人脸与位置。

私按用户隔离

每个账号只看到自己名下的照片，时间线、人脸、地点、相册、收藏、回收站与 AI 搜索统一口径，超管也没有例外；底层索引仍然全局共用，不重复计算。

模模型目录

人脸、OCR、场景、CLIP 四类模型集中查看与切换，能按需下载或替换；AI 队列支持一键暂停 / 恢复。

开只读开放平台

/api/mcp 暴露 6 个只读工具（搜索照片、读时间线、看人物与地点等），用独立令牌鉴权，令牌只在轮换时明文出现一次。

备手机相册备份

整机单配置，按「大小 + 内容 MD5」去重，重复文件直接跳过，不在服务端留第二份。

核心能力 02

影视库：画质、字幕、音轨
都替你想过了

建库、刮削、播放、转码是一条完整链路。手机、电视、桌面各播各的，服务端只负责把对的码流送到对的端。

库四类库各自独立

电影 / 电视剧 / 图片 / 混合四类库，各自有「在主页显示」开关。图片库与混合库有专属网格与全屏查看器：自然序、瀑布流、文件夹层级、封面缩略图开关，全部按库记忆。

画按编码分档

H.264 与 HEVC 各有各的档位表——同码率下 265 能承载更高分辨率。默认档位按「端 + 用户」分别记忆，手机不迁就电视，电视也不迁就手机。

降失败自动降级

HLS fMP4 转码初始化段写绝对路径；转码失败或编码不兼容时，自动回退 H.264 并从原进度续播，安卓端还允许 FFmpeg 软解兜底。

声响度与音轨

可选两遍 loudnorm 响度归一（按库开关），支持降混；没有音轨的视频走「仅转音频」，画面直接复制不重编码，省 CPU。

字字幕不掉黑边

默认字幕语言（简中 / 繁中 / 英文 / 日语 / 韩语 / 不加载）自动匹配同名外挂；内嵌文本轨客户端渲染，PGS / VobSub 图形字幕转码烧录；字幕按真实宽高比避让，始终压在画面上。

满全屏铺满

默认按屏幕铺满，四周不再留黑边；一键切回「适应」保留完整画面。安卓端改原生 PlayerView 的缩放模式，桌面与网页走 cover。

为什么不做全量重传

「同一个文件」判定得足够稳，才敢跳过

同步最怕两件事：该传的没传、传过的反复传。前者靠三向比对，后者靠同一文件判定——大小相等，且修改时间差不超过 2000ms。 并且无论上传还是下载，两端都会把 mtime 回写，所以下一轮不会又认成「新文件」。

  • 设备识别：Windows 用 MachineGuid、macOS 用 IOPlatformUUID、Linux 用 machine-id，同一台机器只算一个设备。
  • 任务粒度：按文件夹建任务，支持包含 / 排除规则，缓存目录与临时文件不会跟着乱跑。
  • 留痕：服务端 /api/sync 命名空间 + 任务表 / 记录表，每次运行都能查到「传了什么、跳过了什么」。

盘符与目录树浏览、上传下载、收藏与最近访问；通过 WebDAV / FTP / SFTP 把磁盘分享出去，也能把网络磁盘挂载回服务器当本地目录用。

密加密空间

AES 加密保存文件，密码加密后存本机数据库；敏感资料单独放一层，不跟普通目录混在一起。

权子账号细粒度权限

应用级白名单 + 路径级权限：哪个账号能用哪个 App、能看哪个目录，都能单独配；管理类应用默认只对管理员可见。

下下载与容器

Transmission BT 下载管理、Docker 镜像容器管理、远程终端（屏蔽 rm、unlink 等敏感命令），都是一个服务端里的独立 App。

监监控与任务

实时 CPU / 内存 / 磁盘 / 网络；后台任务中心能看到索引、转码、识别队列的进度与失败原因。

553个 API 路径（OpenAPI 单一真源）
13个语言包同步维护
26 套运行时主题配色
全本地无公有云依赖
全端覆盖

同一套服务端，四种终端

手机、电脑、电视与网页端共用同一套服务端与数据，各端专注自己的场景；账号、权限、进度全部互通。

服

Windows 服务端

常驻运行的服务核心，提供全部 API、任务队列与存储管理，是整套系统的心脏。安装包 1.26 GB，运行时与模型内置。

桌

Windows 桌面端 / 同步端

WaterNasClient 主客户端管全部应用，WaterNasSync 独立同步端专心同步目录，两者共用一套同步引擎。

端

Android 三端

主端、相册端、音乐端三个 APK 各自独立，图标与启动模式分离，按需安装；装一个也不影响用另一个。

视

TV 与网页端

Android TV / Apple TV 大屏播放，遥控器操作；浏览器直接访问网页端，零安装即可管理，内网也能用。
